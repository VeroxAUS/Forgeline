# Changelog

All notable changes to Forgeline. Versions follow [semantic versioning](https://semver.org/): 1.0.0 is the full release, a major addition bumps the minor number, a bug fix bumps the patch number. The changelog starts with Phase 2.

## Unreleased (0.2.0)

### Added
- Cargo workspace, pinned toolchain, GitHub Actions for format, clippy and tests on Linux and Windows, and a repo hygiene test that keeps saves, dumps, packs and extracted data (and any other commit identity than the allowed ones) out of git. Reviewed and tested by VeroxAUS
- A headless RAM check in CI (`forgeline --headless-check`) that fails above 20 MB private bytes and writes a machine-readable results file (`bench/results/`), plus `docs/ram-log.md`. Reviewed and tested by VeroxAUS
- Automatic discovery of the Steam account, library, Wilds install, build ID and save files (read-only, via `libraryfolders.vdf` and the app manifest), the data-directory rules that refuse Steam, the install and the save folder, and `forgeline-check discover` for PC test rounds. Reviewed and tested by VeroxAUS
- A fixture save builder (`tools/fixture-builder`) that writes small invented saves in the real container format, with expected values next to each, and two committed fixtures. Reviewed and tested by VeroxAUS
- The save reader (`forgeline-save`): opens the save container with the Steam ID, walks the class stream without building a tree of it, and summarises each character slot (equipment box, item box, pouch, found flags, monster kills, active slot). `save-diff` lists which fields differ between two save copies, and `forgeline-check save` reports the counts for PC test rounds. Reviewed and tested by VeroxAUS
- The pack reader and exe scan (`forgeline-pak`): indexes the game's original `re_*.pak` files (never `pak_mods`), reads single entries (stored, deflate, zstd, chunked), resolves a hand-written list of the game files we need by path hash, and rebuilds the save's class and field names from the game exe in a moment (route A), plus `forgeline-check pak` to report all of it. Untested against the real install until the PC round. Reviewed and tested by VeroxAUS
- The update flow (`forgeline-update`) and `forgeline --update`: finds the game and the save, extracts only the needed files from the game's packs into a staging folder in the app's own data folder, rebuilds the save's class names from the exe, checks the result against the last good data (missing files, shrunk categories, files that do not open, an older build or a lost class block it) and swaps it in only if it passes, keeping the old data as `previous`. The second update with nothing new says `Unchanged`. `forgeline-check update` runs it into a dev data folder and can simulate a missing file to see the gate reject it. It runs at below-normal priority, writes only under the data folder and reports progress through `update-status.json`. Untested against the real install until the PC round. Reviewed and tested by VeroxAUS
- The engine (`forgeline-engine`): a low-priority worker thread that keeps one `Snapshot` (what was found, the save summary, the data status and a patch notice) up to date. It shows the last view from a small cache at once, checks in the background whether the save changed, and wakes only on the operating system's file notification (no timer, no polling), after the save has been quiet for 0.5 s. A change during a recompute runs once more; a half-written or locked save keeps the old summary and shows an error. The save is only read: opened with sharing, read whole into memory and checked for unchanged size and modified time. `forgeline-check engine` reports how fast the view appears and how long a new save takes to show up, and the headless RAM check now includes the engine. Untested against the real save until the PC round. Reviewed and tested by VeroxAUS
